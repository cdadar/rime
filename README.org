* 个人的 rime 配置

主力是鼠须管（macOS）。一个双拼方案（小鹤）+ 一个全拼方案（雾凇），都用万象的 LTS 语法模型。

** 方案

| 方案                   | 来源                  | 说明                           |
|------------------------+-----------------------+--------------------------------|
| =double_pinyin_flypy=  | 雾凇（iDvel/rime-ice）| 小鹤双拼（主力）               |
| =rime_ice=             | 雾凇（iDvel/rime-ice）| 雾凇拼音（全拼），与双拼共用词库 |

语法模型（八股文 / librime-octagram）：两个方案都用 =wanxiang-lts-zh-hans.gram=，参数写在各自的
=*.custom.yaml= 里，各自调。模型文件不进 git，用 grammar 配方下载（见下）。

** 更新

上游更新一律走 plum（东风破），不要在本目录里跑 =git pull=。每次两步：先把 plum 的包缓存
拉到上游最新，再用包缓存安装进本目录。

*** 步骤 1：更新包缓存

#+BEGIN_SRC bash
git -C ~/project/source/plum/package/iDvel/ice fetch --depth 1 origin
git -C ~/project/source/plum/package/iDvel/ice reset --hard origin/main
#+END_SRC

（plum 的包缓存是 shallow clone，=git merge --ff-only= 会因历史不连通失败，所以用 =reset --hard=。
包缓存是纯镜像，没有本地改动，reset 安全。）

*** 步骤 2：安装

#+BEGIN_SRC bash
cd ~/project/source/plum/package/iDvel/ice
no_update=1 bash ~/project/source/plum/rime-install iDvel/rime-ice
#+END_SRC

=no_update=1= 表示直接用刚更新的包缓存（省略也行，plum 会自己 fetch，只是控制力差一点）。

*** 其他配方

雾凇的配方路径可以直接指定，例如语法模型（会下载 =wanxiang-lts-zh-hans.gram= 并把补丁
追加到方案 =*.custom.yaml= 末尾的 =__patch:= 块里）：

#+BEGIN_SRC bash
cd ~/project/source/plum/package/iDvel/ice
bash ~/project/source/plum/rime-install iDvel/rime-ice:others/recipes/grammar:schema=double_pinyin_flypy
#+END_SRC

注意：配方追加的 =__patch:= 块（写在文件根层，和 rime-ice 文档里嵌在 =patch:= 内的写法不同）
和你在 =patch:= 里手写的参数会同时存在。2026-09-29 实测：双拼方案那份根层 =__patch:= 是死块，
删掉后 =patch:= 才生效（真正的根因是同一文件里的 =__include: octagram=，见 =AGENTS.md=）；
=radical_pinyin.custom.yaml=、=melt_eng.custom.yaml= 里还有同类块，未验证是否生效。

*** 为什么要先 =cd= 进包目录

plum 的 =scripts/install-packages.sh= 读 recipe 时是这么写的：
=file_patterns=( $(cat recipe | ...) )=。bash 会对命令替换的结果做路径展开，这个展开发生在
*调用时的当前目录*，不是在包目录。所以在 =~/Library/Rime= 里跑，=lua/*.*=、=cn_dicts/*.*=
这些通配符只会匹配到本地已存在的文件 —— 上游 *新增* 的文件会被静默漏掉（还会刷一屏
=ls: ... No such file=），新文件缺失导致方案功能异常。

从包目录里跑，通配符在包目录展开，文件清单才是完整的。

** 本地自定义

自定义都写在 =*.custom.yaml= 里，上游文件保持原样，这样更新时可以放心覆盖。例外：
=rime_ice.dict.yaml= 被就地改过（启用 =cn_dicts/41448= 大字表、追加 =cn_dicts/zhwiki= 和
=cn_dicts/bible=），plum 每次都会把它覆盖回去，更新后要重新打这三行。

=README.md= 已随万象清理删掉，本项目自己的文档就是本文件。

方案 =*.custom.yaml= 末尾由配方追加的 =__patch:= 块（带 =# Rx:= 标记）也是 plum 管理的，
重跑配方会替换，手改会被覆盖。
