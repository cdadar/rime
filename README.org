* 个人的 rime 配置

主力是鼠须管（macOS）。两个小鹤双拼（flypy）键位方案（万象 + 小鹤双拼），另挂一个全拼的雾凇。

** 方案

| 方案                   | 来源                  | 说明                         |
|------------------------+-----------------------+------------------------------|
| =wanxiang_pro=         | 万象（amzxyz）        | 万象词库 + 语法模型 + 辅助码 |
| =double_pinyin_flypy=  | 雾凇（iDvel/rime-ice）| 小鹤双拼                     |
| =rime_ice=             | 雾凇（iDvel/rime-ice）| 雾凇拼音（全拼），与双拼共用词库 |

语法模型（八股文 / librime-octagram）：三个方案都用 =wanxiang-lts-zh-hans.gram= —— 万象写在
=wanxiang_pro.schema.yaml= 里，两个雾凇方案写在各自的 =*.custom.yaml= 里，参数各自调。

** 更新

上游更新一律走 plum（东风破），不要在本目录里跑 =git pull=。每次两步：先把 plum 的包缓存
拉到上游最新，再用包缓存安装进本目录。

*** 步骤 1：更新包缓存

#+BEGIN_SRC bash
git -C ~/project/source/plum/package/iDvel/ice fetch --depth 1 origin
git -C ~/project/source/plum/package/iDvel/ice reset --hard origin/main

git -C ~/project/source/plum/package/amzxyz/rime_wanxiang fetch --depth 1 origin
git -C ~/project/source/plum/package/amzxyz/rime_wanxiang reset --hard origin/wanxiang-flypy-fuzhu
#+END_SRC

（plum 的包缓存是 shallow clone，=git merge --ff-only= 会因历史不连通失败，所以用 =reset --hard=。
包缓存是纯镜像，没有本地改动，reset 安全。）

*** 步骤 2：安装

#+BEGIN_SRC bash
cd ~/project/source/plum/package/iDvel/ice
no_update=1 bash ~/project/source/plum/rime-install iDvel/rime-ice

cd ~/project/source/plum/package/amzxyz/rime_wanxiang
no_update=1 bash ~/project/source/plum/rime-install amzxyz/rime_wanxiang@wanxiang-flypy-fuzhu:plum/full
#+END_SRC

=no_update=1= 表示直接用刚更新的包缓存（省略也行，plum 会自己 fetch，只是控制力差一点）。

*** 其他配方

雾凇的配方路径可以直接指定，例如语法模型（会下载 =wanxiang-lts-zh-hans.gram= 并把补丁
追加到方案 =*.custom.yaml= 末尾的 =__patch:= 块里）：

#+BEGIN_SRC bash
cd ~/project/source/plum/package/iDvel/ice
bash ~/project/source/plum/rime-install iDvel/rime-ice:others/recipes/grammar:schema=double_pinyin_flypy
#+END_SRC

注意：配方追加的 =__patch:= 块和你自己在 =patch:= 里手写的参数会同时存在，两边都改了
=grammar/...= 时以哪个为准不确定，重复了就删掉一块。

*** 为什么要先 =cd= 进包目录

plum 的 =scripts/install-packages.sh= 读 recipe 时是这么写的：
=file_patterns=( $(cat recipe | ...) )=。bash 会对命令替换的结果做路径展开，这个展开发生在
*调用时的当前目录*，不是在包目录。所以在 =~/Library/Rime= 里跑，=lua/*.*=、=cn_dicts/*.*=
这些通配符只会匹配到本地已存在的文件 —— 上游 *新增* 的文件会被静默漏掉（还会刷一屏
=ls: ... No such file=），新文件缺失导致方案功能异常。

从包目录里跑，通配符在包目录展开，文件清单才是完整的。

*** 两个来源共写的文件

万象和雾凇都会往同一个目录写这些名字：=default.yaml=、=weasel.yaml=、=custom_phrase.txt=、
=lua/*=、=opencc/*=、=custom/*=。最后安装的那个覆盖先前的。方案本身不受影响（各自用各自的文件），
但 =lua/number_translator.lua=、=lua/unicode.lua= 这类共享脚本会跟着翻转，出怪问题时先看这里。

** 部署

*** macOS（主力，鼠须管）

菜单栏鼠须管图标 -> 重新部署。验证部署真的跑了：=build/*.prism.bin= 时间戳会更新。

*** linux

fcitx

fcitx5
: ln -s path ~/.local/share/fcitx5/

ibus
: ln -s path ~/.config/ibus/

*** window

默认的配置文件路径获取： =【小狼毫】用户文件夹=
将配置复制到 =C:\Users\Administrator\AppData\Roaming\Rime= 文件下

** 本地自定义

自定义都写在 =*.custom.yaml= 里，上游文件保持原样，这样更新时可以放心覆盖。例外：
=rime_ice.dict.yaml= 被就地改过（启用 =cn_dicts/41448= 大字表、追加 =cn_dicts/zhwiki= 和
=cn_dicts/bible=），plum 每次都会把它覆盖回去，更新后要重新打这三行。

=README.md= 是万象包随附的文档副本，会被 plum 覆盖，不要手改。

方案 =*.custom.yaml= 末尾由配方追加的 =__patch:= 块（带 =# Rx:= 标记）也是 plum 管理的，
重跑配方会替换，手改会被覆盖。
