* 个人的 rime 配置

主力是鼠须管（macOS）。三套方案：小鹤双拼（主力）、雾凇全拼、小鹤音形。双拼与全拼同用万象的 LTS 语法模型。

** 方案

| 方案                  | 来源                            | 说明                             |
|-----------------------+---------------------------------+----------------------------------|
| =double_pinyin_flypy= | 雾凇（iDvel/rime-ice）          | 小鹤双拼（主力）                 |
| =rime_ice=            | 雾凇（iDvel/rime-ice）          | 雾凇拼音（全拼），与双拼共用词库 |
| =flypy=               | 小鹤音形（cubercsl/rime-flypy） | 小鹤音形（音+形四码），独立码表  |

语法模型（八股文 / librime-octagram）：两个方案都用 =wanxiang-lts-zh-hans.gram=，来自 RIME-LMDG 的
LTS release（grammar 配方下载，见下）。参数写在各自的 =*.custom.yaml= 里；双拼那份用的就是配方 /
RIME-LMDG 的推荐值，改的时候两边一起改。

** 更新

上游更新一律走 plum（东风破），不要在本目录里跑 =git pull=。每次两步：先把 plum 的包缓存
拉到上游最新，再用包缓存安装进本目录。

*** 步骤 1：更新包缓存

#+BEGIN_SRC bash
git -C ~/project/source/plum/package/iDvel/ice fetch --depth 1 origin
git -C ~/project/source/plum/package/iDvel/ice reset --hard origin/main
#+END_SRC

（plum 的包缓存是 shallow clone，=git merge --ff-only= 会因历史不连通失败，所以用 =reset --hard=。
包缓存是纯镜像，没有本地改动，reset 安全。）

*** 步骤 2：安装

#+BEGIN_SRC bash
cd ~/project/source/plum/package/iDvel/ice
no_update=1 bash ~/project/source/plum/rime-install iDvel/rime-ice
#+END_SRC

=no_update=1= 表示直接用刚更新的包缓存（省略也行，plum 会自己 fetch，只是控制力差一点）。

*** 其他配方

雾凇的配方路径可以直接指定，例如语法模型（会下载 =wanxiang-lts-zh-hans.gram= 并给方案打补丁）：

#+BEGIN_SRC bash
cd ~/project/source/plum/package/iDvel/ice
bash ~/project/source/plum/rime-install iDvel/rime-ice:others/recipes/config:schema=double_pinyin_flypy
bash ~/project/source/plum/rime-install iDvel/rime-ice:others/recipes/grammar:schema=double_pinyin_flypy
#+END_SRC

配方会在文件末尾追加一个根层 =__patch:= 块（带 =# Rx:= 标记），跑完要按「本地自定义」说的清掉。

*** 小鹤音形（=cubercsl/rime-flypy=）

小鹤音形（音+形四码）不在雾凇包里，单独装；码表从官方鼠须管挂接包提取：

#+BEGIN_SRC bash
cd ~/project/source/plum/package/cubercsl/flypy
no_update=1 bash ~/project/source/plum/rime-install cubercsl/rime-flypy
#+END_SRC

装出来：=flypy.schema.yaml=（小鹤音形）、=flypydz.*=（反查）、=flypyok.*=（ok 拼字）、
=flypy/*.dict.yaml=（拆分的码表）、=lua/flypy_*.lua=。与 =double_pinyin_flypy= 零文件重叠，互不影响，
两者在 =default.custom.yaml= 的 =schema_list= 里并列。

用户词库用纯文本（升级不会被覆盖）：=flypy.user.txt=（普通词，候选排在主码表之后）、
=flypy.user.top.txt=（置顶词）。每行 =词条<Tab>编码[<Tab>权重]=，必须用 Tab 分隔，改完重新部署。
（旧版 YAML 用户词库 =flypy/flypy.user*.dict.yaml= 已不再读取。）

*** 为什么要先 =cd= 进包目录

plum 的 =scripts/recipe.sh= 读 recipe 时是这么写的：
=file_patterns=( $(cat recipe | ...) )=。bash 会对命令替换的结果做路径展开，这个展开发生在
*调用时的当前目录*，不是在包目录。所以在 =~/Library/Rime= 里跑，=lua/*.*=、=cn_dicts/*.*=
这些通配符只会匹配到本地已存在的文件 —— 上游 *新增* 的文件会被静默漏掉（还会刷一屏
=ls: ... No such file=），新文件缺失导致方案功能异常。

从包目录里跑，通配符在包目录展开，文件清单才是完整的。

** 本地自定义

自定义都写在 =*.custom.yaml= 里，上游文件保持原样，这样更新时可以放心覆盖。例外：
=rime_ice.dict.yaml= 被就地改过（启用 =cn_dicts/41448= 大字表、追加 =cn_dicts/zhwiki= 和
=cn_dicts/bible=），plum 每次都会把它覆盖回去，更新后要重新打这三行。

配方（=config=/=grammar=）跑完会在文件末尾追加一个根层 =__patch:= 块（带 =# Rx:= 标记），内容是
=patch/+:=，即往本文件的 =patch= 再叠一层。*这层是活的，而且优先级更高*：同名键以它为准，手写的值
会被顶掉——实测 =default.custom.yaml= 那份会把 =schema_list= 从「小鹤 + 雾凇」两项顶成只剩小鹤一项，
方案选单里直接少了雾凇。所以*跑完要删掉它*，前提是配方参数已直写在 =patch:= 里（recipe 只负责生成；
删掉后重跑配方会再生成，属于 plum 的正常行为）。验证：部署后看 =build/default.yaml= 的 =schema_list=。
（=radical_pinyin.custom.yaml=、=melt_eng.custom.yaml= 的值已就位，只有换拼音方案时才需要重跑 =config=。）
